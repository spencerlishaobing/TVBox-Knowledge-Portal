## 已取得的证据

影视仓 6.2.8 已恢复三个业务 DEX，并取得部分真实 Java 业务代码；仍有 native 方法需要恢复。反编译 Java 可能错误表达异常范围，重要分支使用 fallback 控制流复核。

Android TVBoxOS 已完成现有环境的离线增量构建。已有安装版本的首页、聚合搜索及详情经过观察，但安装 APK 与当前构建的指纹不同，不能混用验收结论。

## 后续新增的部分验证

配置导入已补充多仓识别与旧请求失效保护；直播已有本地样片播放、失败地址恢复和配置推送证据。投屏接收已具备设置入口与等待页，在单设备真实 TCP SOAP 测试中起播超过十秒，并完成暂停、GENA 通知和退出清理检查。

这些不代表核心点播、真实直播、手机投屏互通或完整影视仓复刻已经验收。最新投屏补丁仍需独立构建复核，旧补丁的成功记录不自动适用于新版本。

## 当前差异

- 影视仓保留独立播放与详情预览两条路径。
- 播放器暂停标记和 Surface 恢复行为不同。
- Android 运行日志确认认证失败也会进入错误回退并切换来源。
- 已检查的请求边界不能完整区分用户取消、认证要求和可重试错误。

## 接下来

优先完成首页、分类、搜索、详情、选集、点播与网盘认证的完整使用流程，然后处理真实直播和设置回归；投屏扩展不挤占核心流程。按功能需要补齐相关 native 依赖。保留现有请求结果过滤和播放器恢复保护。所有核心流程需 Android 可视化验收，播放需达到十秒基准。

完整教程、版本指纹、原始反编译结果及未脱敏材料保存在私有知识库。尚未完成全功能复刻，不发布“全部兼容”或“全部验收通过”的结论。
